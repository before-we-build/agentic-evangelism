# Сделать готовое видео видимым на Android

[English](android.md) · [Русский](android.ru.md) · [Українська](android.uk.md)

## Сканирование из Termux без ADB

После сохранения проверенного MP4 в общей папке Downloads выполните команду на телефоне в Termux или Ubuntu/PRoot с подключённым путём Termux. Замените пример имени реальным коротким именем ASCII:

```sh
/data/data/com.termux/files/usr/bin/am broadcast --user 0 \
  -a android.intent.action.MEDIA_SCANNER_SCAN_FILE \
  -d file:///storage/emulated/0/Download/TikTok_song.mp4
```

Пример использует профиль владельца Android `0`; для другой настройки берите фактический профиль. Обёртка Termux `am` должна существовать. На этом телефоне команда без `--user 0` завершилась ошибкой разрешения `INTERACT_ACROSS_USERS`. Для имён с пробелами или не-ASCII символами создайте закодированный URI файла (например, через Python `Path.as_uri()`) и передайте его одним аргументом.

Ожидаемый ответ: `Broadcast sent without waiting for result`. Он подтверждает только принятие запроса сканирования. Немного подождите, закройте и заново откройте выбор TikTok и найдите точное имя в «Видео» или Downloads. 14.09.2026 пользователь подтвердил, что `TikTok_Blazhenni.mp4` виден там после этого запроса на телефоне проекта. Это подтверждает видимость в выборе, а не момент индексации или гарантированный результат на других устройствах. Если выбор не проверен, сообщите, что индексация не подтверждена.

Android [помечает эту рассылку устаревшей с API 29](https://developer.android.com/reference/android/content/Intent#ACTION_MEDIA_SCANNER_SCAN_FILE); проверяйте результат на каждом устройстве. Не устанавливайте инструменты и не меняйте разрешения только ради сканирования одного файла.

## Необязательный резервный способ с ADB

Используйте только разрешённое подключённое устройство. Запустите `adb devices`; явно выберите нужное устройство через `-s SERIAL`. Если устройств несколько и выбор неясен, уточните. Не используйте старый беспроводной адрес: он меняется.

Проверьте файл на телефоне, а не только внутри PRoot. Примеры предполагают простое имя латиницей, подготовленное скилом:

```sh
adb -s SERIAL shell ls -l /storage/emulated/0/Download/TikTok_peace.mp4
adb -s SERIAL shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file:///storage/emulated/0/Download/TikTok_peace.mp4
adb -s SERIAL shell content query --uri content://media/external/video/media --projection _id:_display_name:relative_path --where "\"_display_name='TikTok_peace.mp4'\""
```

Успешная рассылка команды сама по себе не доказывает индексацию. Подтвердите строку ответа с нужным именем и `relative_path=Download/`. Для других имён правильно экранируйте аргументы оболочки Android и кодируйте URI файлов; не вставляйте произвольные имена в команды. Простые имена ASCII позволяют избежать этой хрупкой операции.

Поддержка рассылки и разрешения зависят от версии Android. Если запрос сначала не вернул строку, немного подождите и повторите один раз. Если файла всё ещё нет, сообщите, что индексация не подтверждена, и изучите ошибку; не повторяйте бесконечно и не меняйте системные разрешения.

Если файл проиндексирован, но список выбора устарел: закройте и заново откройте его, выберите «Видео» или «Обзор» → внутренняя память → Download и найдите точное имя. Уточняйте вид окна выбора только если эти действия не помогли. Если ни один способ не подтвердил видимость, найдите и откройте MP4 в приложении «Файлы» и снова откройте выбор. Строка MediaStore или видимость в выборе не доказывают публикацию или успешную загрузку.

Практический вывод: наличие файла и правильные кодеки ещё не доказывают его видимость в выборе. Короткое имя упрощает поиск; сканирование добавляет запись в библиотеку Android. Одно лишь кириллическое имя не доказывает причину проблемы с видимостью.
