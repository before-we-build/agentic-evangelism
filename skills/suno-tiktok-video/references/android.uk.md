# Зробити готове відео видимим на Android

[English](android.md) · [Русский](android.ru.md) · [Українська](android.uk.md)

## Сканування з Termux без ADB

Після збереження перевіреного MP4 у спільній папці Downloads виконайте команду на телефоні в Termux або Ubuntu/PRoot із підключеним шляхом Termux. Замініть приклад назви реальною короткою назвою ASCII:

```sh
/data/data/com.termux/files/usr/bin/am broadcast --user 0 \
  -a android.intent.action.MEDIA_SCANNER_SCAN_FILE \
  -d file:///storage/emulated/0/Download/TikTok_song.mp4
```

Приклад використовує профіль власника Android `0`; для іншого налаштування беріть фактичний профіль. Обгортка Termux `am` має існувати. На цьому телефоні команда без `--user 0` завершилася помилкою дозволу `INTERACT_ACROSS_USERS`. Для назв із пробілами чи не-ASCII символами створіть закодований URI файла (наприклад, через Python `Path.as_uri()`) і передайте його одним аргументом.

Очікувана відповідь: `Broadcast sent without waiting for result`. Вона підтверджує лише прийняття запиту сканування. Трохи зачекайте, закрийте й знову відкрийте вибір TikTok та знайдіть точну назву у «Відео» або Downloads. 14.09.2026 користувач підтвердив, що `TikTok_Blazhenni.mp4` видно там після цього запиту на телефоні проєкту. Це підтверджує видимість у виборі, а не момент індексації чи гарантований результат на інших пристроях. Якщо вибір не перевірено, повідомте, що індексацію не підтверджено.

Android [позначає цю розсилку застарілою від API 29](https://developer.android.com/reference/android/content/Intent#ACTION_MEDIA_SCANNER_SCAN_FILE); перевіряйте результат на кожному пристрої. Не встановлюйте інструменти й не змінюйте дозволи лише задля сканування одного файла.

## Необов’язковий резервний спосіб з ADB

Використовуйте лише дозволений під’єднаний пристрій. Запустіть `adb devices`; явно виберіть потрібний пристрій через `-s SERIAL`. Якщо пристроїв кілька й вибір неясний, уточніть. Не використовуйте стару бездротову адресу: вона змінюється.

Перевірте файл на телефоні, а не лише всередині PRoot. Приклади передбачають просте ім’я латиницею, підготовлене скілом:

```sh
adb -s SERIAL shell ls -l /storage/emulated/0/Download/TikTok_peace.mp4
adb -s SERIAL shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file:///storage/emulated/0/Download/TikTok_peace.mp4
adb -s SERIAL shell content query --uri content://media/external/video/media --projection _id:_display_name:relative_path --where "\"_display_name='TikTok_peace.mp4'\""
```

Успішна розсилка команди сама собою не доводить індексацію. Підтвердьте рядок відповіді з потрібним ім’ям і `relative_path=Download/`. Для інших імен правильно екрануйте аргументи оболонки Android і кодуйте URI файлів; не вставляйте довільні імена в команди. Прості імена ASCII дозволяють уникнути цієї крихкої операції.

Підтримка розсилки й дозволи залежать від версії Android. Якщо запит спочатку не повернув рядок, трохи зачекайте й повторіть один раз. Якщо файла досі немає, повідомте, що індексацію не підтверджено, і вивчіть помилку; не повторюйте нескінченно й не змінюйте системні дозволи.

Якщо файл проіндексовано, але список вибору застарів: закрийте й заново відкрийте його, виберіть «Відео» або «Огляд» → внутрішня пам’ять → Download і знайдіть точне ім’я. Уточнюйте вигляд вікна вибору лише якщо ці дії не допомогли. Якщо жоден спосіб не підтвердив видимість, знайдіть і відкрийте MP4 у застосунку «Файли» та знову відкрийте вибір. Рядок MediaStore чи видимість у виборі не доводять публікацію або успішне завантаження назовні.

Практичний висновок: наявність файла й правильні кодеки ще не доводять його видимість у виборі. Коротке ім’я спрощує пошук; сканування додає запис до бібліотеки Android. Саме лише кириличне ім’я не доводить причину проблеми з видимістю.
