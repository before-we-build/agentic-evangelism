# Параллельные иллюстрации для раскадровки

[English](SKILL.md) · [Русский](SKILL.ru.md) · [Українська](SKILL.uk.md)

Этот скилл организует создание независимых иллюстраций. Проверьте, какой инструмент изображений действительно доступен в среде. В Codex следуйте установленному скиллу `imagegen` и по умолчанию используйте встроенный `image_gen`. Установка этой папки не устанавливает сервис, не разрешает внешний API и не гарантирует доступ к двум провайдерам.

Задайте единый визуальный стиль и неизменное описание персонажа. Создайте и просмотрите стилевой образец, затем тестовую сцену с другого ракурса. Это зависимости, требующие просмотра: одного сохранения файла недостаточно для запуска зависимых сцен. Присвойте каждому объекту постоянный ID; сохраняйте по нему точный промпт, референсы, маршрут, попытки, результат просмотра и путь к изображению. После проверки загружайте все пригодные маршруты готовыми объектами. Сохраняйте пригодные иллюстрации рядом с раскадровкой и используйте успешные результаты при возобновлении.

## Адаптивный план конкурентности

Перед генерацией составьте список маршрутов. Проверьте настоящую операцию изображений, право доступа и предоставленное разрешение для задачи. Различайте потребительскую подписку, отдельно оплачиваемый API и локальный генератор. Сами по себе бинарник, вход или название тарифа не доказывают доступность изображений или лимит одновременных запросов. Где возможно, используйте проверки состояния без изменений; отсутствующие сведения отмечайте явно. Живая проба расходует ресурсы и должна укладываться в предоставленное разрешение. При подготовке профилей или запуске планировщика прочитайте [проверку провайдеров и порядок запуска](references/providers.ru.md).

Для каждого маршрута сохраните датированные доказательства доступа со сроком действия, тип подписки, поддержку изображений/референсов и применимые лимиты. Одновременные запросы, запросы за промежуток времени, остаток квоты и деньги — отдельные ограничения. Маршруты с общей квотой учётной записи или проекта используют одну группу квоты и общее состояние планировщика, в том числе между процессами. Неизвестная квота не означает неограниченную; неизвестная стоимость не равна нулю. Не превращайте процент использования или название тарифа в выдуманное количество изображений.

Используйте документированную или разрешённую средой верхнюю границу параллельности. Если ёмкость неизвестна, начните с одного запроса и после успешной работы увеличивайте нагрузку постепенно, только до явно разрешённого предела пробы. Успешный запрос показывает, что этот уровень сработал один раз; он не устанавливает максимум провайдера. Заполняйте каждый освободившийся слот сразу, когда позволяют зависимости, квоты, бюджет и паузы. Медленный запрос AGY не должен задерживать готовую работу на доступном маршруте Codex. Предпочитайте маршруты, сохраняющие необходимые референсы и согласованность персонажей; свободные слоты не оправдывают отказ от этих требований.

При временном ограничении частоты соблюдайте указанную провайдером задержку, снижайте параллельность и ограничивайте число повторов с нарастанием пауз. Исчерпанная квота, потеря доступа и постоянные ошибки требуют иной реакции, чем временные. Прерванный запрос или запрос с истёкшим временем ожидания уже мог создать изображение: выясните результат перед повторной отправкой. Не включайте непроверенный маршрут и не тратьте средства на новый запасной сервис ради заполнения свободных слотов. Сохраняйте успешные изображения и возобновляйте только незавершённые пригодные ID.

## Запуск и просмотр

`scripts/generate.py` содержит локальный планировщик и необязательный запуск CLI-адаптеров. Проверяйте профиль через `--profiles /private/routes.json --plan`, а установленные команды-кандидаты — через `--discover`. Эти проверки не генерируют изображений. `--probe-codex` читает очищенные от частных идентификаторов данные учётной записи и использования, если это поддерживается; он не проверяет маршрут изображений и не выводит их количество из процентов использования.

Для встроенных инструментов используйте описанный в справке процесс `--action next` / `--action record`. Резервируйте работу до вызова `image_gen`, сразу записывайте каждый результат, затем заполняйте свободную ёмкость. В режиме кода поддерживайте ограниченный набор активных вызовов через `Promise.race` или пул исполнителей; дождитесь каждого запущенного вызова до завершения выполнения кода. `Promise.allSettled` может собрать итоговые результаты, но не должен задерживать новую работу в свободных слотах до завершения всей волны. Вызывайте `tools.image_gen__imagegen` один раз для каждого зарезервированного объекта и передавайте настоящие необходимые референсы. Python-помощник сам не вызывает встроенный инструмент.

Для проверенного внешнего CLI-адаптера `--action run --allow-external-cli` запускает настроенную команду со структурированными входом и выходом. Профиль также должен содержать право доступа, разрешение и действующие доказательства; флаг команды их не предоставляет. Автоматического адреса генерации AGY, Codex или бесплатного сервиса нет. `--dry-run` — локальная проверка планировщика, создающая крошечные заглушки, непригодные для видео.

Просматривайте каждое изображение. Разрешайте зависимые сцены лишь после проверки визуальной согласованности и политики песни; сохраняйте оригиналы и используйте новые файлы для изменений. Записывайте настоящих провайдеров и изменения параллельности в метаданные генерации. Одновременная отправка характеризует локальное планирование, а не одновременную обработку внутри провайдера. Сообщайте о завершённых/просмотренных объектах, повторах, причинах ожидания и неизвестных лимитах без заявлений о глобально оптимальной скорости.

Применяйте визуальную политику песни, по умолчанию `evangelical_baptist`: Писание, молитва, общение, служение и творение по смыслу текста. Исключайте нимбы, культовые иконы, иконостасы, луковичные купола и незапрошенные облачения. Уважайте явный выбор сцены, например `interdenominational_unity`. Сохраняйте иллюстрации рядом с раскадровкой, а не только в папке генератора.
