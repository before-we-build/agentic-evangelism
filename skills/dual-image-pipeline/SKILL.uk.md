# Паралельні ілюстрації для розкадрування

[English](SKILL.md) · [Русский](SKILL.ru.md) · [Українська](SKILL.uk.md)

Цей скіл організовує створення незалежних ілюстрацій. Перевірте, який інструмент зображень справді доступний у середовищі. У Codex дотримуйтеся встановленого скіла `imagegen` і за замовчуванням використовуйте вбудований `image_gen`. Встановлення цієї папки не встановлює сервіс, не дозволяє зовнішній API і не гарантує доступу до двох провайдерів.

Задайте єдиний візуальний стиль і незмінний опис персонажа. Створіть і перегляньте стильовий зразок, а потім тестову сцену з іншого ракурсу. Це залежності, що потребують перегляду: самого збереження файла недостатньо для запуску залежних сцен. Надайте кожному об'єкту сталий ID; зберігайте за ним точний промпт, референси, маршрут, спроби, результат перегляду та шлях до зображення. Після перевірки завантажуйте всі придатні маршрути готовими об'єктами. Зберігайте придатні ілюстрації поряд із розкадруванням і використовуйте успішні результати під час відновлення.

## Адаптивний план конкурентності

Перед генерацією складіть перелік маршрутів. Перевірте справжню операцію зображень, право доступу та наданий дозвіл для завдання. Розрізняйте споживчу підписку, окремо оплачуваний API та локальний генератор. Самі по собі бінарник, вхід чи назва тарифу не доводять доступності зображень або ліміту одночасних запитів. Де можливо, використовуйте перевірки стану без змін; відсутні відомості позначайте явно. Жива проба витрачає ресурси й має вкладатися в наданий дозвіл. Готуючи профілі чи запускаючи планувальник, прочитайте [перевірку провайдерів і порядок запуску](references/providers.uk.md).

Для кожного маршруту збережіть датовані докази доступу зі строком чинності, тип підписки, підтримку зображень/референсів і застосовні ліміти. Одночасні запити, запити за часовий проміжок, залишок квоти та гроші — окремі обмеження. Маршрути зі спільною квотою облікового запису чи проєкту використовують одну групу квоти та спільний стан планувальника, зокрема між процесами. Невідома квота не означає необмежену; невідома вартість не дорівнює нулю. Не перетворюйте відсоток використання чи назву тарифу на вигадану кількість зображень.

Використовуйте документовану або дозволену середовищем верхню межу паралельності. Якщо місткість невідома, почніть з одного запиту й після успішної роботи збільшуйте навантаження поступово, лише до явно дозволеної межі проби. Успішний запит показує, що цей рівень спрацював одного разу; він не встановлює максимум провайдера. Заповнюйте кожен звільнений слот відразу, коли дозволяють залежності, квоти, бюджет і паузи. Повільний запит AGY не має затримувати готову роботу на доступному маршруті Codex. Віддавайте перевагу маршрутам, що зберігають необхідні референси та узгодженість персонажів; вільні слоти не виправдовують відмови від цих вимог.

За тимчасового обмеження частоти дотримуйтеся вказаної провайдером затримки, знижуйте паралельність і обмежуйте кількість повторів із наростанням пауз. Вичерпана квота, втрата доступу й постійні помилки потребують іншої реакції, ніж тимчасові. Перерваний запит або запит із перевищеним часом очікування вже міг створити зображення: з'ясуйте результат перед повторним надсиланням. Не вмикайте неперевірений маршрут і не витрачайте кошти на новий запасний сервіс заради заповнення вільних слотів. Зберігайте успішні зображення й відновлюйте лише незавершені придатні ID.

## Запуск і перегляд

`scripts/generate.py` містить локальний планувальник і необов'язковий запуск CLI-адаптерів. Перевіряйте профіль через `--profiles /private/routes.json --plan`, а встановлені команди-кандидати — через `--discover`. Ці перевірки не генерують зображень. `--probe-codex` читає очищені від приватних ідентифікаторів дані облікового запису й використання, якщо це підтримується; він не перевіряє маршрут зображень і не виводить їхню кількість із відсотків використання.

Для вбудованих інструментів використовуйте описаний у довідці процес `--action next` / `--action record`. Резервуйте роботу до виклику `image_gen`, відразу записуйте кожен результат, а потім заповнюйте вільну місткість. У режимі коду підтримуйте обмежений набір активних викликів через `Promise.race` або пул виконавців; дочекайтеся кожного запущеного виклику до завершення виконання коду. `Promise.allSettled` може зібрати підсумкові результати, але не має затримувати нову роботу у вільних слотах до завершення цілої хвилі. Викликайте `tools.image_gen__imagegen` один раз для кожного зарезервованого об'єкта й передавайте справжні потрібні референси. Python-помічник сам не викликає вбудований інструмент.

Для перевіреного зовнішнього CLI-адаптера `--action run --allow-external-cli` запускає налаштовану команду зі структурованими входом і виходом. Профіль також має містити право доступу, дозвіл і чинні докази; прапорець команди їх не надає. Автоматичної адреси генерації AGY, Codex чи безплатного сервісу немає. `--dry-run` — локальна перевірка планувальника, що створює крихітні заглушки, непридатні для відео.

Переглядайте кожне зображення. Дозволяйте залежні сцени лише після перевірки візуальної узгодженості та політики пісні; зберігайте оригінали й використовуйте нові файли для змін. Записуйте справжніх провайдерів і зміни паралельності в метадані генерації. Одночасне надсилання характеризує локальне планування, а не одночасну обробку всередині провайдера. Звітуйте про завершені/переглянуті об'єкти, повтори, причини очікування й невідомі ліміти без заяв про глобально оптимальну швидкість.

Застосовуйте візуальну політику пісні, за замовчуванням `evangelical_baptist`: Писання, молитва, спілкування, служіння й творіння за змістом тексту. Виключайте німби, культові ікони, іконостаси, цибулясті бані та незапитані облачення. Поважайте явний вибір сцени, наприклад `interdenominational_unity`. Зберігайте ілюстрації поряд із розкадруванням, а не лише в папці генератора.
