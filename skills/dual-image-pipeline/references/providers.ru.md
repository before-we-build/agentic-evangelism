# Справочник провайдеров генерации изображений

[English](providers.md) · [Русский](providers.ru.md) · [Українська](providers.uk.md)

В этом документе описаны технические спецификации, нативные разрешения, правила параллелизма и логика переключения при ошибках (failover) для двухвендорного конвейера.

## 1. Antigravity (`agy` / Gemini Image)

- **Движок**: Gemini 3.1 Flash Image.
- **Нативное разрешение**:
  - Вертикальное (`9:16`): $768 \times 1376$ (~1.05 Мп, кратно патчам 16/32).
  - Горизонтальное (`16:9`): $1376 \times 768$.
  - Квадрат (`1:1`): $1024 \times 1024$.
- **Время генерации**: ~10–14 секунд на кадр.
- **Рекомендуемый параллелизм**: 3–4 одновременных запроса в пачке.
- **Коды ошибок**:
  - `429 / RESOURCE_EXHAUSTED`: Достигнут лимит частоты запросов или сессии. Вызывает автоматическую передачу оставшихся сцен в пул Codex.

## 2. OpenAI Codex (`codex` / GPT-Image 2.5)

- **Движок**: GPT-Image 2.5 Flare (оптимизирован для скорости) и Sunburst.
- **Нативное разрешение**:
  - Вертикальное (`9:16`): $1024 \times 1792$ (~1.83 Мп).
  - Горизонтальное (`16:9`): $1792 \times 1024$.
  - Квадрат (`1:1`): $1024 \times 1024$.
- **Время генерации**: ~12–18 секунд на кадр.
- **Рекомендуемый параллелизм**: 1–2 одновременных запроса в пачке.
- **Коды ошибок**:
  - `429 / rate_limit_exceeded`: Достигнут минутный или скользящий лимит подписки. Вызывает автоматическую передачу оставшихся сцен в пул AGY.

## 3. Высокоскоростная параллельная диспетчеризация

Для раскадровки из $N$ сцен:
- Сцены распределяются между пулами: AGY обрабатывает пачку $A$ (например, четные номера сцен), а Codex — пачку $B$ (нечетные номера).
- Если один из пулов освобождается раньше, он забирает оставшиеся задачи из общей очереди.
- Если вендор возвращает ошибку лимита, его очередь незамедлительно перенаправляется второму здоровому вендору.
- Готовые файлы проверяются на валидность заголовков изображений и сохраняются по путям, указанным в раскадровке.
