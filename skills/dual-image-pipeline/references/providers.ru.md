# Проверка провайдеров изображений

[English](providers.md) · [Русский](providers.ru.md) · [Українська](providers.uk.md)

## Установить настоящий маршрут доступа

При наличии встроенного инструмента Codex `image_gen` используйте его по умолчанию. Проверьте настоящие инструменты активной среды. Локальный планировщик учитывает работу, а среда вызывает инструмент. Команда-кандидат, вход и успешный вывод справки сами по себе не подтверждают генерацию изображений.

На ранее проверенном телефоне Android/PRoot `agy generate-image --help` возвращал общую справку. Это наблюдение не доказывает ни работоспособность команды изображений, ни отсутствие инструментов изображений в каждой версии AGY. Действующая документация Antigravity описывает инструмент генерации изображений и headless-интерфейс агента с событиями инструментов; перед настройкой адаптера проверьте установленную версию и операцию, которая действительно создаёт файл. [Модели](https://antigravity.google/docs/models), [headless-интерфейс](https://antigravity.google/docs/cli/headless/).

Квоты Antigravity зависят от тарифа и объёма работы, имеют временные окна и необязательные дополнительные расходы кредитов. Документированная `/usage` (`/quota`) открывает интерактивную панель квоты; это не документированный универсальный JSON-интерфейс состояния. В существующем терминальном сеансе AGY введите `/usage`; ожидается панель квот. Используйте только поддерживаемый адаптер чтения или подтверждённые пользователем наблюдения; не извлекайте учётные данные и не выдумывайте `agy quota --json`. [Тарифы](https://antigravity.google/docs/plans), [панель квоты](https://antigravity.google/docs/cli/commands/usage/).

Генерация изображений Codex использует общую квоту подписки; доступ через API-ключ оплачивается по правилам API. В существующем терминальном сеансе Codex `/status` показывает остаток использования. `python3 scripts/generate.py --probe-codex` при наличии поддержки использует операции чтения учётной записи/состояния и удаляет идентификаторы; она не разрешает и не проверяет генерацию изображений. Процент использования не устанавливает остаток изображений или верхнюю границу параллельности. [Квоты Codex и оплата изображений](https://learn.chatgpt.com/docs/pricing).

Лимиты API могут независимо ограничивать запросы, изображения, токены и расходы и быть общими для моделей, проекта или организации. Читайте настоящие лимиты учётной записи/модели и метаданные ответов. Считайте `Retry-After` минимальной паузой, отличайте временную перегрузку от исчерпанной квоты и ограничивайте повторы. Адаптеры должны отключать скрытые автоматические повторы или явно учитывать их. [Лимиты OpenAI API](https://developers.openai.com/api/docs/guides/rate-limits).

Источники проверены 2026-09-15; обновляйте проверку перед использованием меняющихся условий продуктов. Здесь нет встроенных числовых лимитов параллельности провайдеров. Pollinations или другой внешний сервис требует собственной проверенной операции, действующих доказательств доступа/стоимости и предоставленного разрешения; запасной адрес не выбирается автоматически.

## Профили маршрутов и доказательства

Храните наблюдения об учётной записи, профили маршрутов и состояние планировщика в личной рабочей папке вне репозитория. Для `quota_group` используйте псевдоним без персональных данных; не храните токены, адреса электронной почты или настройки учётной записи. Формат профилей — `{"schema_version":1,"routes":[...]}`. Каждый маршрут содержит:

| Поле | Значение |
| --- | --- |
| `id`, `kind` | Постоянный ID; `host_tool`, `cli` или `local`. |
| `quota_group` | Область общего учёта. Маршруты с общей квотой используют одну группу и файл состояния. |
| `image_capability`, `entitlement`, `authorized` | Настоящая поддержка изображений, право `verified` и разрешение для задачи. Необходимые значения true/verified должны отражать доказательства, а не желаемое состояние. |
| `subscription` | `{kind: subscription/api/local, plan: ...}`; название тарифа никогда не задаёт ёмкость. |
| `evidence` | `source`: `host_tool`, `provider_status`, `user_confirmed` или `authorized_smoke_test`; `checked_at` и `expires_at` — секунды Unix. Просроченные доказательства блокируют новые запросы. |
| `supports_references` | True только для маршрута с проверенной поддержкой референсов. |
| `limits` | `max_parallel`, `initial_parallel`; необязательные `requests_per_minute`, `requests_per_day`, `remaining_requests`, `reset_at`. Значения должны означать настоящее количество запросов. |
| `limits.quota_windows` | Необязательные наблюдения в исходных единицах: `used_percent`, `window_minutes`, `resets_at`. Исчерпанные окна блокируют до получения свежих доказательств; не переводите проценты в количество изображений. |
| `cost` | `per_request` — проверенная верхняя денежная граница за попытку; платным маршрутам также нужен `budget_remaining`. В группе квоты используйте одну `currency`. Неизвестная цена блокирует запросы. |
| `overage_disabled`, `zero_cost_verified` | Маршрут подписки с нулевой ценой требует проверенного `overage_disabled:true`; маршрут API с нулевой ценой — `zero_cost_verified:true`. Включённое использование всё равно может расходовать квоту. |
| `command`, `timeout_seconds` | Массив аргументов CLI/локального адаптера и время ожидания. Команда должна реализовать описанный ниже структурированный контракт. |

Если одна группа квоты охватывает несколько ограничений, используйте самое строгое применимое общее ограничение. Планировщик соблюдает настроенные лимиты количества запросов, параллельности и денег; он не может вывести расход токенов/кредитов из тарифа или гарантировать учёт постороннего трафика вне общего состояния. Обновляйте наблюдения, когда другие сеансы используют ту же учётную запись. Проценты квоты остаются наблюдениями, а не полной моделью учёта запросов с переменной стоимостью.

Если провайдер не раскрывает параллельность, начните с одного запроса и перед повышением `max_parallel` запишите явно разрешённый ограниченный предел пробы. `initial_parallel` задаёт осторожное начало; успешная работа позволяет постепенный рост до верхней границы, ограничение частоты снижает её. Не используйте давний успешный запуск как бессрочное доказательство. Само время восстановления не оправдывает пополнение неизвестной квоты.

`status_source:"codex_app_server"` подключает маршрут к поддерживаемому обновлению состояния Codex. Добавьте `--refresh-codex-status` к `next`/`run`, чтобы обновить данные при этом запуске. Это не создаёт автоматического сервиса опроса, не проверяет поддержку изображений, не включает платный перерасход и не обходит просроченные доказательства.

## Планирование, резервирование, выполнение, запись

Запускайте приведённые команды из папки этого скилла. На Android используйте ту же оболочку Termux/PRoot, где работают Python и выбранный генератор. Замените `/private/...` собственными доступными личными путями. Ожидаются JSON-планы, резервирования и отчёты о состоянии.

```sh
python3 scripts/generate.py --discover
python3 scripts/generate.py --profiles /private/routes.json --plan
python3 scripts/generate.py --storyboard /private/song/storyboard.json --profiles /private/routes.json --state /private/image-shared.sqlite --run-id song --action next
```

`--discover` сообщает только о кандидатах в PATH; `--plan` проверяет пригодность и неизвестные данные без вызовов или резервирования. `next` резервирует пригодную работу до генерации. Все процессы с общей квотой должны использовать один файл состояния, а возобновление той же раскадровки — тот же ID запуска. Отдельные файлы состояния не координируются между собой.

Объекты поддерживают `depends_on`, `reference_asset_ids`, `review_required`, `reviewed`, `review_token`, `allowed_routes`, `requires_references` и `affinity_group`. Явно задайте образец → проба переноса → зависимые сцены через `depends_on`; для образца/пробы установите `review_required:true`. Используйте `reference_asset_ids` для передачи сгенерированных образцов в зависимые вызовы; это также устанавливает зависимости. После просмотра изображения установите для объекта `reviewed:true` и `review_token`, равный точному `token` из ответа `record`, и возобновите работу. Токен привязывает проверку к этому файлу; старое логическое значение не может подтвердить новое изображение. Удерживайте повторяющиеся образы на совместимом маршруте через `affinity_group`; требования к референсам остаются обязательными. Сохраняйте предоставленные `characters[].avatar_image` и `assets[].character_ids`.

`limits.remaining_checked_at` и `cost.budget_checked_at` определяют независимые снимки остатков. Обновление процентов квоты не должно возобновлять старый денежный бюджет. `--action status` показывает состояние планировщика без запуска запросов. `--dry-run` использует отдельный файл состояния с суффиксом `.dry-run`. По умолчанию результаты сохраняются рядом с раскадровкой, поэтому её относительные пути остаются действительными; другая выходная папка требует проверки путей экспортированной раскадровки перед сборкой видео.

Для каждого возвращённого резервирования запускайте ровно один соответствующий вызов встроенного инструмента с его промптом и необходимыми референсами. Сохраните изображение, просмотрите его и запишите структурированный результат в личный файл, например `{"status":"success","output":"/private/song/images/scene01.png"}`. Затем зарегистрируйте его с ID работы и токеном резервирования, которые вернул `next`:

```sh
python3 scripts/generate.py --storyboard /private/song/storyboard.json --profiles /private/routes.json --state /private/image-shared.sqlite --run-id song --action record --job-id scene01 --token LEASE_TOKEN --result /private/result.json
```

Токен резервирования — локальные данные планировщика, не учётные данные API. Записывайте завершения сразу и снова вызывайте `next`, пока другие изображения ещё генерируются. Не ждите завершения всей волны перед заполнением свободной ёмкости. Всегда дожидайтесь всех запущенных вызовов среды до завершения выполнения кода.

Состояния результата: `success`, `review_required`, `rate_limited`, `transient_error`, `quota_exhausted`, `unauthorized`, `permanent_error` или `ambiguous`; результаты, допускающие повтор, могут содержать `retry_after` в секундах. Истёкшее время ожидания или потерянный ответ могут означать успешную удалённую работу. Оставляйте неоднозначные задачи для выяснения результата; не повторяйте их наугад или уже завершённые объекты. Возобновление должно сохранять оригиналы, а изменения требуют новых путей/ID вместо перезаписи успешного результата.

## Необязательные CLI-адаптеры

`--action run --allow-external-cli` запускает только пригодные настроенные CLI/локальные адаптеры. Каждая команда получает JSON через stdin с промптом, `reference_images`, путём результата и сведениями о работе и возвращает JSON через stdout по контракту результатов выше. Общий ответ агента CLI сам по себе не является изображением: проверяйте настоящий файл. Адаптеры должны учитывать референсы, соблюдать разрешения среды, сохранять файлы и точно сообщать об ошибках провайдера. Не реализуйте текстовый запасной маршрут для сцены, зависящей от аватара.

`--dry-run` используйте только для локальных проверок планировщика; крошечные заглушки не являются готовыми иллюстрациями. Предоставленное ранее разрешение может охватывать маршрут, но ни флаги конфигурации, ни копирование скилла не предоставляют новых прав на сервис, расходы, публикацию или удаление.
