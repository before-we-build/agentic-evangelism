# Довідник провайдерів генерації зображень

[English](providers.md) · [Русский](providers.ru.md) · [Українська](providers.uk.md)

У цьому документі описано технічні специфікації, нативні роздільні здатності, правила паралелізму та логіку перемикання при помилках (failover) для двовендорного конвеєра.

## 1. Antigravity (`agy` / Gemini Image)

- **Рушій**: Gemini 3.1 Flash Image.
- **Нативна роздільна здатність**:
  - Вертикальна (`9:16`): $768 \times 1376$ (~1.05 Мп, кратно патчам 16/32).
  - Горизонтальна (`16:9`): $1376 \times 768$.
  - Квадрат (`1:1`): $1024 \times 1024$.
- **Час генерації**: ~10–14 секунд на кадр.
- **Рекомендований паралелізм**: 3–4 одночасні запити у пачці.
- **Коди помилок**:
  - `429 / RESOURCE_EXHAUSTED`: Досягнуто ліміт частоти запитів або сесії. Викликає автоматичну передачу залишкових сцен у пул Codex.

## 2. OpenAI Codex (`codex` / GPT-Image 2.5)

- **Рушій**: GPT-Image 2.5 Flare (оптимізовано для швидкості) та Sunburst.
- **Нативна роздільна здатність**:
  - Вертикальна (`9:16`): $1024 \times 1792$ (~1.83 Мп).
  - Горизонтальна (`16:9`): $1792 \times 1024$.
  - Квадрат (`1:1`): $1024 \times 1024$.
- **Час генерації**: ~12–18 секунд на кадр.
- **Рекомендований паралелізм**: 1–2 одночасні запити у пачці.
- **Коди помилок**:
  - `429 / rate_limit_exceeded`: Досягнуто хвилинний або ковзний ліміт підписки. Викликає автоматичну передачу залишкових сцен у пул AGY.

## 3. Швидкісна паралельна диспетчеризація

Для розкадровки з $N$ сцен:
- Сцени розподіляються між пулами: AGY обробляє пачку $A$ (наприклад, парні номери сцен), а Codex — пачку $B$ (непарні номери).
- Якщо один із пулів звільняється раніше, він забирає залишкові завдання зі спільної черги.
- Якщо вендор повертає помилку ліміту, його черга негайно перенаправляється до іншого працездатного вендора.
- Готові файли перевіряються на валідність заголовків зображень і зберігаються за шляхами, вказаними в розкадровці.
