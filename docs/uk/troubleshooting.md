# Якщо щось не працює

Українська · [Русский](../ru/troubleshooting.md) · [English](../en/troubleshooting.md)

Це розширена довідка для того, хто допомагає з налаштуванням. Якщо ви тут уперше, почніть із [короткої допомоги](help.md).

Почніть із точної помилки й екрана, де вона виникла: Android, Termux, Ubuntu чи Codex. Скопіюйте коротке повідомлення про помилку, а не всю приватну сесію чи конфігурацію. Перед публічним зверненням по допомогу приховайте коди входу, токени, адреси електронної пошти й назви особистих файлів.

## Команду не знайдено

`pkg` і `termux-setup-storage` слід запускати в **Termux**. `apt`, встановлений `ffmpeg` і `codex` із цього посібника — в **Ubuntu**. Якщо ви всередині Ubuntu, а потрібен Termux, спочатку вийдіть із Codex, потім введіть `exit` у командному рядку Ubuntu. Знову увійти до Ubuntu можна так:

```sh
proot-distro login ubuntu --bind /storage/emulated/0:/storage/emulated/0
```

Якщо `codex` усе ще не знаходиться всередині Ubuntu, перевірте крок встановлення через npm. Якщо npm повідомляє про несумісний рушій або версію, запишіть результат `node --version` і помилку, перш ніж пробувати інший спосіб встановлення. Не запускайте завантажені програми «виправлення» з невідомих джерел.

## Вхід у Codex не завершується

Залишайте термінал відкритим, поки входите в браузері на тому самому телефоні. Тимчасовий код може втратити чинність; знову запустіть команду входу, щоб отримати новий. Якщо вхід за кодом пристрою не дозволений, перевірте налаштування облікового запису або скористайтеся звичайним входом через браузер за командою `codex login`. Ніколи не вставляйте дані входу в чат. [Довідка про вхід](https://developers.openai.com/codex/auth/).

## Немає Завантажень або відмовлено в доступі

У налаштуваннях Android перевірте дозвіл Termux на доступ до файлів. Якщо доступ ще не надано, виконайте `termux-setup-storage` у Termux. Знову увійдіть до Ubuntu за наведеною вище командою підключення сховища й перевірте:

```sh
ls /storage/emulated/0/Download
```

Посібник використовує цей повний шлях безпосередньо. Зручне посилання на зразок `~/storage/downloads` необов’язкове. Не створюйте заново й не перезаписуйте наявну папку лише для збігу шляхів.

## Навички немає в списку

Перезапустіть Codex і перевірте `/skills`. Програма встановлення за замовчуванням використовує `~/.agents/skills/suno-tiktok-video`. Старіше встановлення може використовувати інший каталог. Запитайте Codex, з якого каталогу він справді завантажує навички. Якщо він явно використовує `~/.codex/skills`, вийдіть із Codex і виконайте в папці проєкту:

```sh
python3 scripts/install_skill.py --destination ~/.codex/skills
```

Не встановлюйте дублікати в різних місцях лише щоб спробувати всі варіанти. Якщо програма встановлення повідомляє про наявну копію, вона навмисно залишила її без змін. Попросіть помічника порівняти дві папки й підготувати оновлення для перевірки або для цього завдання явно вкажіть шлях репозиторію `skills/suno-tiktok-video/SKILL.md`. Копіювання навички не може додати недоступний інструмент зображень.

## Помічник повідомляє про помилку пісочниці або bwrap

На перевіреному телефоні Android ARM64, в Ubuntu через Termux/PRoot із Codex CLI 0.154.0 неодноразово виникало `bwrap: Can't get type of source /tmp/codex-bwrap-synthetic-mount-targets-0: No such file or directory`. Запитана команда ще не запускалася. Каталог був видимий через `ls`, але `bwrap` не міг підключити його за віртуальним шляхом `/tmp`; підключення того самого каталогу за реальним шляхом rootfs PRoot проходило. На цьому телефоні проблему локалізовано на межі перетворення шляхів PRoot і `bwrap`. Це не доводить, що всі встановлення PRoot поводяться однаково.

**Де: у командному рядку Ubuntu всередині Termux, після виходу з Codex.** Перевірте ті самі параметри пісочниці, не змінюючи конфігурацію Codex:

```sh
rootfs=$(readlink -f /proc/self/root)
TMPDIR="$rootfs/tmp" codex sandbox -c sandbox_mode=workspace-write -c sandbox_workspace_write.exclude_slash_tmp=true -- /bin/true
echo $?
```

**Очікуваний результат:** команда пісочниці нічого не виводить, а `echo $?` показує `0`. На перевіреному телефоні пройшли і цей тест, і створення тимчасового файлу. Якщо перевірка не вдалася, збережіть короткий текст нової помилки; не припускайте наперед, що причина та сама.

Щоб відкрити нову розмову з Codex із цими параметрами, у тій самій Ubuntu виконайте:

```sh
rootfs=$(readlink -f /proc/self/root)
TMPDIR="$rootfs/tmp" codex -c sandbox_workspace_write.exclude_slash_tmp=true
```

**Очікуваний результат:** Codex відкривається звичайно. Повторюйте цю команду для наступних сесій або попросіть помічника підготувати й перевірити запускник `~/.local/bin/codex`, який задає обидва параметри та викликає справжній виконуваний файл Codex. На перевіреному телефоні такий запускник встановлено й перевірено через `codex sandbox`; повне встановлення на чистому телефоні та всі інтерактивні сценарії не перевірялися. Перед використанням запускника перевірте `command -v codex`. Не робіть необмежений доступ налаштуванням за замовчуванням. Якщо кероване середовище забороняє цей спосіб, зупиніться й зверніться до його адміністратора.

## Збирання відео зупинилося або вихідний файл уже існує

Зберігайте оригінальну пісню та попереднє відео. Використайте нову назву вихідного файлу; допоміжна програма навмисно відмовляється перезаписувати наявний. Попросіть помічника перевірити вільне місце, доступ до файлів, формат аудіо та чи дорівнює сума тривалостей сцен точній тривалості пісні. Усі картинки, на які посилається план, мають існувати. Незавершений MP4 не є готовим результатом.

Під час тривалого збирання відео тримайте Termux відкритим. Якщо Android постійно зупиняє його у фоні, перегляньте налаштування батареї для Termux. Назви меню залежать від виробника. Нагрітому телефону може знадобитися час охолонути; не запускайте кілька повторних збірок поспіль.

## Відео є у Файлах, але його немає в TikTok

Спочатку відкрийте MP4 через **Файли → Завантаження**. Закрийте й знову відкрийте вибір файлів у TikTok, оберіть Відео або Огляд/Завантаження та знайдіть точну назву. Коротка назва полегшує пошук; не було доведено, що зафіксовану проблему спричинили кириличні назви.

Якщо це не допомогло, запитайте сканування без ADB. На телефоні виконайте команду в Termux або Ubuntu/PRoot із підключеним шляхом Termux, замінивши `TikTok_song.mp4` реальною назвою готового відео:

```sh
/data/data/com.termux/files/usr/bin/am broadcast --user 0 \
  -a android.intent.action.MEDIA_SCANNER_SCAN_FILE \
  -d file:///storage/emulated/0/Download/TikTok_song.mp4
```

Очікувана відповідь: `Broadcast sent without waiting for result`. Трохи зачекайте, знову відкрийте вибір TikTok і шукайте у «Відео» або Downloads. На телефоні проєкту користувач підтвердив видимість `TikTok_Blazhenni.mp4` після цього запиту. Сама відповідь не підтверджує індексацію; якщо файла досі немає, скористайтеся «Файлами» або необов’язковим способом ADB нижче. Для назв, яким потрібен закодований URI, дивіться [довідку скілла для Android](../../skills/suno-tiktok-video/references/android.uk.md).

ADB — необов’язковий резервний спосіб для вже підключеного телефона. Наведений нижче спосіб для досвідченіших користувачів також застосовувався на телефоні проєкту; інша версія Android може поводитися інакше.

### Необов’язково: підключіть телефон до самого себе через ADB

Android 11 і новіші версії мають бездротове налагодження. Користуйтеся довіреною мережею Wi-Fi. Відкрийте **Налаштування → Про телефон** і кілька разів натисніть **Номер збірки**, доки не ввімкнуться параметри розробника; у деяких виробників цей пункт розташований у відомостях про програмне забезпечення. Відкрийте **Параметри розробника → Бездротове налагодження**, увімкніть його й оберіть **Сполучити пристрій за допомогою коду**. Назви можуть відрізнятися. [Інструкція Android ADB](https://developer.android.com/tools/adb#wireless-android11-command-line).

Тримайте діалог сполучення видимим у розділеному екрані разом із Termux. Під час зафіксованої спроби перемикання застосунку закривало його й спричиняло `connection refused`.

**Усередині Ubuntu** за потреби встановіть ADB:

```sh
apt update
apt install adb
```

Наступні команди — шаблони, їх не слід вставляти без змін. Візьміть `PHONE_ADDRESS` і `PAIR_PORT` із **діалогу з кодом сполучення** та підставте їх нижче. Код сполучення вводьте лише в локальному терміналі, коли він попросить:

```sh
adb pair PHONE_ADDRESS:PAIR_PORT
```

Після успішного сполучення поверніться до **головного екрана бездротового налагодження**. Показані там IP-адреса й порт — це `PHONE_ADDRESS` і `CONNECT_PORT` для наступної команди. Цей порт підключення відрізняється від порту сполучення:

```sh
adb connect PHONE_ADDRESS:CONNECT_PORT
adb devices
```

Ознака успіху: ваш пристрій з’явився зі станом `device`. Нижче замість `SERIAL` використовуйте ідентифікатор із результату `adb devices`. Ніколи не копіюйте стару адресу з чужої інструкції. Якщо показано кілька пристроїв, явно оберіть потрібний телефон.

### Необов’язково: проскануйте й перевірте один готовий файл

Для файлу, який справді називається `TikTok_song.mp4`, замініть `SERIAL` і виконайте:

```sh
adb -s SERIAL shell ls -l /storage/emulated/0/Download/TikTok_song.mp4
adb -s SERIAL shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file:///storage/emulated/0/Download/TikTok_song.mp4
adb -s SERIAL shell content query --uri content://media/external/video/media --projection _id:_display_name:relative_path --where "\"_display_name='TikTok_song.mp4'\""
```

Послідовно використовуйте справжню назву свого вихідного файлу в усіх трьох командах. Якщо вона містить пробіли чи спеціальні символи, попросіть помічника правильно оформити лапки. Сам успіх команди broadcast не є підтвердженням: останній запит має показати назву файлу та `relative_path=Download/`. Якщо запису немає, трохи зачекайте й повторіть запит один раз. Якщо його все ще немає, вкажіть, що додавання до медіатеки не підтверджено, та скористайтеся Файлами; не змінюйте системні дозволи навмання.

Після успішного сканування знову відкрийте вибір файлів. Коли закінчите, вимкніть бездротове налагодження. Додавання до медіатеки не означає, що відео завантажене на платформу чи опубліковане.
