# Підтримка та перевірені результати

Українська · [Русский](../ru/maintenance.md) · [English](../en/maintenance.md)

## Що є в цьому репозиторії

Посібники для людей містяться в `docs/en`, `docs/ru` та `docs/uk`. Кореневий README — вступна сторінка трьома мовами. Кожен посібник має однакову назву файлу в усіх трьох папках. Навичка міститься в `skills/suno-tiktok-video`; `SKILL.md` — основний англомовний файл, який читає помічник, поруч є російська й українська копії для читання. Ці копії описують той самий процес, а не три різні навички. Довідкові документи також мають переклади. Назви в коді Python і команди оболонки залишаються незмінними в усіх мовах.

`scripts/install_skill.py` встановлює лише папку навички. Він не встановлює сторонні інструменти, не змінює дозволи чи налаштування облікового запису й нічого не публікує. Якщо папка призначення вже існує, він відмовляється продовжувати. Передавайте `--destination PATH` лише коли знаєте, який каталог навичок використовує ваше встановлення Codex.

## Що насправді перевірили

12 вересня 2026 року відповідальний за проєкт попросив переглянути локальну історію сесій Codex. Використано лише відповідні технічні етапи; самі сесії, налаштування облікових записів, токени, ідентифікатори пристроїв, особисті пісні та картинки сюди не включено.

| Дані перевірки | Результат і його межі |
| --- | --- |
| Доступні сесії від 4 вересня 2026 року | Linux і Codex уже були встановлені. Початкове встановлення й перший вхід відновити не вдалося. |
| Середовище телефона, спостережене у вересні | Android ARM64, Termux, Ubuntu 26.04 через PRoot; Node 22.22.1 та Codex 0.153.2. Це зафіксовані версії, а не універсальні мінімальні вимоги. |
| 9 вересня: ADB | ADB встановлено всередині Ubuntu; бездротове сполучення виконано без комп’ютера. Розділений екран дозволив тримати діалог сполучення відкритим. |
| 12 вересня: сховище | Завантаження Android були доступні для читання; створено посилання на них у Linux. У посібнику натомість можна користуватися повним шляхом Android. |
| 12 вересня: медіаінструменти | FFmpeg встановлено в Ubuntu; збирання відео на повну пісню, перевірки декодування аудіо/відео та запит MediaStore завершилися успішно. |
| 12 вересня: робота з ілюстраціями | На телефоні створено шість статичних картинок, одинадцять сцен і повний MP4 тривалістю 122,2 секунди з розміром кадру 1080×1920. Перевірено відео H.264, аудіо AAC і додавання до медіатеки Android. Зміни картинок були приблизними; синхронізацію з текстом не перевіряли. |
| Паралельна генерація | Незалежні запити до вбудованого інструмента запущено одночасно; контрольованого порівняння швидкості не проводили, а сервіс може ставити запити у внутрішню чергу. |
| Доступ до зображень | У зафіксованій сесії був вбудований інструмент зображень. У нових встановленнях та інших облікових записах його може не бути. |
| Пісочниця | Виникла локальна помилка `bwrap`. Загального виправлення або необхідності необмеженого режиму не встановлено. |

Початковий спосіб встановлення відновлено за документацією та спостереженим робочим середовищем. Ми не повторювали повне встановлення на чистому телефоні. Для оновлення цієї таблиці потрібні фактичні результати перевірки; успішна перевірка синтаксису не означає успішного встановлення на Android.

## Джерела для налаштування

Перевірено 12 вересня 2026 року. Сервіси та версії пакетів можуть змінюватися; якщо крок відрізняється, орієнтуйтеся на актуальну офіційну сторінку.

- [Встановлення Termux](https://github.com/termux/termux-app#installation) і [завантаження з F-Droid](https://f-droid.org/en/packages/com.termux/).
- [PRoot-Distro](https://github.com/termux/proot-distro): встановлення, вхід і підключення сховища.
- [Codex CLI](https://developers.openai.com/codex/cli/) та [довідник CLI](https://developers.openai.com/codex/cli/reference/).
- [Вхід у Codex](https://developers.openai.com/codex/auth/).
- [Локальні навички Codex](https://developers.openai.com/codex/skills/).
- [Бездротовий ADB в Android](https://developer.android.com/tools/adb#wireless-android11-command-line).

Допоміжні програми для відео скопійовані з робочої навички `suno-tiktok-video` відповідального за проєкт. Із публічних інструкцій прибрано залежності від особистого процесу LabelGrid та шляху до особистої допоміжної програми; приватні інструкції не поширюються. Паралельна генерація, збереження повного аудіо, відмова від перезапису, перегляд зображень і фінальна перевірка залишаються частиною навички. Окрема вбудована навичка чи сервіс `imagegen` тут не поширюється.

## Як внести зміни, не порушивши відповідність мов

1. Опишіть зміну та її вплив на користувача.
2. Оновіть відповідні англійський, російський та український посібники разом, включно з командами й застереженнями. Так само оновлюйте переклади навички та довідкових матеріалів.
3. Запустіть локальні перевірки з кореня репозиторію:

```sh
python3 scripts/check_docs.py
python3 -m unittest discover -s tests -v
```

4. Якщо змінюється допоміжна програма для медіа, також виконайте коротку пробну збірку зі згенерованим аудіо та сценами через FFmpeg і перегляньте результат. Зберігайте тестові медіафайли поза файлами, що відстежуються в репозиторії.
5. Перед публікацією перегляньте `git diff` та `git status --short`. Додавайте до коміту лише заплановані файли проєкту. Не додавайте домашній каталог Codex, експорти сесій, файли облікових записів чи резервні копії телефона.

Автоматична перевірка документації перевіряє наявність відповідних файлів різними мовами та локальні посилання; вона не може засвідчити якість перекладу, богословську правильність чи доступність сервісів. Тести перевіряють програму встановлення й окремі функції допоміжних програм без зовнішніх облікових записів або витрат на генерацію зображень.

## Як долучитися або оновити свою копію

Щоб запропонувати покращення, створіть issue на GitHub: укажіть крок посібника, мову, за потреби модель телефона й версію Android, а також коротке повідомлення про помилку без приватних даних. Ніколи не додавайте файли авторизації чи повну приватну сесію. Невелике запропоноване виправлення корисне, навіть якщо ви не вмієте програмувати.

Щоб оновити локальну копію, у якій ви нічого не змінювали, вийдіть із Codex, перейдіть до папки репозиторію всередині Ubuntu й виконайте:

```sh
git status --short
```

Якщо нічого не виведено, команда не знайшла локальних змін. Якщо вона показує зміни, які ви хочете зберегти, попросіть допомогти їх зберегти, перш ніж продовжувати. Коли локальну копію не змінено, виконайте:

```sh
git pull --ff-only
```

Оновлення репозиторію не перезаписує встановлену навичку; порівнюйте й оновлюйте ту копію окремо. Автоматична публікація, облікові записи дистрибуції та масові звернення до людей не входять до цього початкового процесу.
