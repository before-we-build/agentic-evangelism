# Налаштуйте телефон з Android

Українська · [Русский](../ru/phone-setup.md) · [English](../en/phone-setup.md)

Усе можна зробити на одному телефоні. Тримайте цю сторінку відкритою в браузері й переходьте до Termux, коли про це сказано. Якщо телефон підтримує розділений екран, так буде зручніше.

Посібник поєднує досвід роботи на телефоні з кроками встановлення, відновленими за актуальною документацією. Збережені сесії починаються вже після першого встановлення, тому чисте встановлення за цим посібником **не перевірене** від початку до кінця. Дивіться, [що саме перевіряли](maintenance.md). Android/PRoot — спосіб, який використовує спільнота, а не обіцянка офіційної підтримки Codex.

## Перед початком

За можливості користуйтеся Wi-Fi: встановлення Linux та його інструментів потребує завантаження значного обсягу даних. Залиште кілька вільних гігабайтів і дайте телефону час завершити роботу. Не видаляйте наявний Termux, щоб почати заново: у його приватних файлах можуть бути ваша робота й дані входу.

Прочитайте пояснення, скопіюйте лише вміст відповідного блоку команд, вставте у вказаний екран і натисніть Enter. Дочекайтеся завершення команди й повернення рядка, у якому можна вводити текст. Якщо команда повідомляє про помилку, зупиніться на цьому кроці та відкрийте [усунення несправностей](troubleshooting.md); не вставляйте наступні кроки поверх помилки. Не вводьте символи `$` чи `#`, якими на чужому знімку термінала позначено початок командного рядка.

## 1. Встановіть і відкрийте Termux

На телефоні відкрийте [сторінку Termux у F-Droid](https://f-droid.org/en/packages/com.termux/), завантажте APK і відкрийте завантажений файл. Android може попросити дозволити встановлення з цього браузера. Дозвольте його лише для цього запланованого встановлення. Відкрийте Termux і дочекайтеся завершення першого налаштування. Доповнення Termux завантажуйте з того самого джерела. [Інструкція встановлення Termux](https://github.com/termux/termux-app#installation).

**У Termux** оновіть список інструментів:

```sh
pkg update
pkg upgrade
```

Прочитайте кожен запит підтвердження перед тим, як погодитися. Запит на зразок `Do you want to continue? [Y/n]` очікує вашої відповіді: введіть `y` і натисніть Enter, щоб продовжити заплановане встановлення. Якщо незнайомий запит стосується налаштувань або заміни файлів, попросіть допомоги перед вибором. Повідомлення про пакети, що прокручуються на екрані, — звичайна річ. Ознака успіху: команда завершилася, і ви знову можете вводити текст.

## 2. Надайте Termux доступ до Завантажень

**У Termux** виконайте:

```sh
termux-setup-storage
```

Погодьтеся із запитом Android на доступ до файлів, а потім перевірте:

```sh
ls ~/storage/downloads
```

Ознака успіху: ви бачите назви файлів із папки Завантаження телефона або порожній список, якщо папка порожня. Повідомлення `Permission denied` означає, що доступу немає. Робіть це в Termux, а не всередині Ubuntu. Якщо наявне встановлення вже показує файли, не повторюйте налаштування сховища.

## 3. Встановіть Ubuntu всередині Termux

**У Termux** встановіть програму керування середовищами:

```sh
pkg install proot-distro
```

Перевірте, чи середовище вже є:

```sh
proot-distro list
```

Якщо Ubuntu вже встановлена, використовуйте її; не скидайте її. Інакше встановіть:

```sh
proot-distro install ubuntu
```

Це може тривати деякий час. Потім увійдіть до Ubuntu й явно надайте їй доступ до спільного сховища телефона:

```sh
proot-distro login ubuntu --bind /storage/emulated/0:/storage/emulated/0
```

Ознака успіху: вигляд командного рядка змінився. Слово `root` тут означає користувача середовища Linux; для цього налаштування не потрібно отримувати root-права в Android. Команди Ubuntu нижче слід вводити в цьому новому екрані. Перевірте:

```sh
cat /etc/os-release
ls /storage/emulated/0/Download
```

Ви маєте побачити інформацію про Ubuntu й назви завантажених файлів. [Інструкція PRoot-Distro](https://github.com/termux/proot-distro#quick-start). Версія встановленої системи може відрізнятися від зафіксованої Ubuntu 26.04; не замінюйте робоче середовище лише заради збігу версій.

## 4. Встановіть робочі інструменти

**Усередині Ubuntu** виконайте:

```sh
apt update
apt install nodejs npm git python3 ffmpeg ca-certificates
```

Ці пакети потрібні для запуску помічника, завантаження проєкту, допоміжних програм і збирання відео. Перевірте кожен:

```sh
node --version
npm --version
python3 --version
ffmpeg -version
ffprobe -version
```

Ознака успіху: з’являється інформація про версії. У зафіксованому налаштуванні використовувався Node 22.22.1. Якщо встановлення Codex нижче повідомить про непідтримувану версію Node, збережіть помилку й попросіть допомогти оновити Node в Ubuntu; оновлення Node в Termux змінить інше середовище.

## 5. Встановіть Codex та увійдіть

**Усередині Ubuntu** встановіть офіційний npm-пакет, який використовується в цьому процесі:

```sh
npm install -g @openai/codex
codex --version
```

Ознака успіху: Codex показує версію. Зафіксована версія — 0.153.2; команда може встановити новіший випуск. [Codex CLI](https://developers.openai.com/codex/cli/).

Почніть вхід:

```sh
codex login --device-auth
```

Відкрийте показане посилання в браузері **на цьому самому телефоні**, увійдіть і введіть тимчасовий код. Можливо, у налаштуваннях безпеки облікового запису доведеться дозволити вхід за кодом пристрою. Поверніться до Termux і перевірте:

```sh
codex login status
```

Вхід за кодом пристрою залежить від налаштувань облікового запису. Якщо він недоступний, спробуйте `codex login` і відкрийте показане посилання на телефоні. Нікому не надсилайте код або свій `auth.json`. Вхід через ChatGPT та оплата API — різні способи доступу; цей посібник використовує вхід через ChatGPT. [Офіційна інструкція входу](https://developers.openai.com/codex/auth/).

## 6. Завантажте проєкт і встановіть його навичку

**Усередині Ubuntu** збережіть проєкт у приватному сховищі Linux. Готові відео натомість зберігайте в Завантаженнях Android.

```sh
mkdir -p ~/projects
cd ~/projects
git clone https://github.com/before-we-build/agentic-evangelism.git
cd agentic-evangelism
```

Якщо `agentic-evangelism` уже існує, перейдіть до нього командою `cd ~/projects/agentic-evangelism`; не видаляйте його й не намагайтеся клонувати поверх нього.

Наступна команда копіює навичку в каталог користувацьких навичок Codex і відмовляється перезаписувати наявну копію:

```sh
python3 scripts/install_skill.py
```

Ознака успіху: з’являється шлях встановлення, що закінчується на `suno-tiktok-video`. Це копіює інструкції роботи, а не сервіс генерації зображень. Сучасний Codex читає користувацькі навички з `~/.agents/skills`; деякі старіші встановлення використовують `~/.codex/skills`. Якщо навичка не з’явилася, дивіться [усунення несправностей](troubleshooting.md). [Пошук локальних навичок](https://developers.openai.com/codex/skills/).

## 7. Запустіть помічника

**Усередині Ubuntu**, з папки проєкту:

```sh
codex
```

Прочитайте запити довіри та дозволів; довіряйте цьому проєкту лише якщо хочете дозволити йому працювати з цими файлами. Усередині **Codex** введіть `/skills` і знайдіть `suno-tiktok-video`. Потім надішліть таке повідомлення звичайною мовою:

> Перевір, чи доступні навичка suno-tiktok-video, ffmpeg, ffprobe та доступ до Завантажень Android. Також перевір, чи може ця сесія справді генерувати й зберігати картинки. Поки нічого не генеруй і не витрачай гроші. Поясни простими словами, чого бракує.

Якщо генерація картинок недоступна, попросіть запити для сцен, створіть картинки в інструменті, яким уже користуєтеся, збережіть їх у Завантаження й прямо попросіть Codex використати ці файли. Дивіться [перше відео](first-video.md). У новому встановленні Codex можуть бути інші інструменти, ніж у зафіксованій сесії.

Усе готово, коли помічник може читати Завантаження, запускати програму збирання відео та має або доступний інструмент зображень, або обрані вами локальні картинки. ADB і LabelGrid необов’язкові й для цього етапу не потрібні.

## Коли наступного разу відкриєте телефон

**Як зрозуміти, де я зараз?** Якщо ви бачите розмову з помічником, ви в Codex; натисніть Ctrl+C за підказкою, щоб повернутися до командного рядка. У командному рядку виконайте `cat /etc/os-release`. Якщо результат називає Ubuntu, ви вже всередині Ubuntu. Якщо файлу немає, спробуйте `command -v pkg`: шлях із `com.termux` означає, що ви в Termux. Якщо жодна ознака не підходить, попросіть допомоги, а не входьте навмання до ще одного середовища Linux.

Відкрийте Termux. Якщо ви вже всередині Ubuntu, пропустіть першу команду. Інакше:

```sh
proot-distro login ubuntu --bind /storage/emulated/0:/storage/emulated/0
```

**Усередині Ubuntu**:

```sh
cd ~/projects/agentic-evangelism
codex
```

`codex resume` дозволяє обрати попередню розмову. Щоб вийти з Codex, натисніть Ctrl+C за підказкою; у Termux є клавіша Ctrl в додатковому ряду клавіш. Введіть `exit` у командному рядку Ubuntu, щоб повернутися до Termux. Щоразу встановлювати все заново не потрібно.

Продовжуйте до [першого відео](first-video.md).
