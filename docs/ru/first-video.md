# Создайте первое видео

[Українська](../uk/first-video.md) · Русский · [English](../en/first-video.md)

Сначала завершите [настройку телефона](phone-setup.md). Эта страница предполагает, что Codex уже запущен внутри Ubuntu и видит скилл.

## 1. Сохраните песню на телефоне

Скачайте выбранную запись из Suno или другого источника, который вы имеете право использовать. Нажмите «Скачать» в сервисе и дождитесь завершения загрузки. Откройте в Android **Файлы → Загрузки** и убедитесь, что песня на месте. Расположение кнопок скачивания и доступные форматы зависят от учётной записи. Скилл не создаёт учётную запись Suno и не скачивает песню по закрытой ссылке.

Запомните имя файла. Если версий несколько, укажите нужную. Более новый файл не обязательно лучше, а его дата не доказывает, откуда он взят. Сохраните исходную запись.

## 2. Дайте Codex задание

Вставьте это в **Codex**, а не в командную строку Ubuntu. Замените пример имени файла своим:

> Используй $suno-tiktok-video. Моя песня «My song.mp3» лежит в загрузках Android. Сделай вертикальное видео 1080×1920 на полную песню с несколькими неподвижными иллюстрациями по смыслу текста. Генерируй независимые картинки параллельно. Покажи, какой аудиофайл выбран. Прочитай встроенный текст песни; если его нет, попроси текст у меня. Моменты смены картинок могут быть приблизительными, без караоке и субтитров. Сохрани новый MP4 в загрузки с коротким именем файла. Проверь готовое видео и то, видит ли его Android. Не публикуй его.

Если точно нужна последняя загрузка, можно сказать: «Используй последний полностью скачанный аудиофайл в загрузках». Помощник должен показать полный путь, размер и время изменения. Если подходят два файла, он должен предложить вам выбрать.

Помощник прочитает текст, объяснит основные идеи иллюстраций, сделает картинки, соберёт видео на полную песню и проверит MP4. Песня сохраняется целиком; по умолчанию между неподвижными картинками используются простые смены кадра. Время сцен выбирается приблизительно при монтаже, а не по проверенным отметкам слов или припевов.

## 3. Если помощнику чего-то не хватает

**В аудиофайле нет текста:** вставьте текст, который действительно использовался в песне, или укажите соответствующий локальный текстовый файл. Не просите угадывать куплеты по названию.

**В сеансе нет инструмента изображений:** попросите по одному описанию для генерации картинки на каждую основную идею. Создайте картинки в инструменте, к которому у вас уже есть доступ, скачайте их, затем явно скажите Codex, какие файлы использовать. Попросите осмотреть картинки перед монтажом. Такая ручная передача изображений поддерживается; это не автоматическая встроенная генерация. Генерация через API — отдельный необязательный путь с отдельной настройкой и возможными расходами; скилл не должен переходить на него незаметно.

Можно использовать и свои готовые картинки, не регистрируясь в сервисе изображений. В приложении «Файлы» Android скопируйте выбранные картинки в «Загрузки»; удерживайте каждую копию и выберите «Переименовать», например в `scene-01.jpg` и `scene-02.jpg`. Сохраняйте настоящее расширение: переименование PNG в JPG не преобразует формат. Затем отправьте Codex такое сообщение, указав свои имена файлов:

> Используй мои готовые картинки из загрузок: сначала scene-01.jpg, затем scene-02.jpg. Осмотри обе и скажи, передают ли они основные идеи песни. Если нужны ещё картинки, объясни, чего не хватает, до сборки видео. Используй эти файлы вместо генерации изображений, сохрани песню целиком и запиши новый вертикальный MP4 в загрузки. Не публикуй его.

Перечислите в сообщении все выбранные картинки. Скилл может повторно использовать подходящую картинку для повторяющегося припева. Для этого варианта нужны ваши картинки; новые ИИ-иллюстрации по-прежнему требуют доступа к отдельному сервису изображений.

**Появился запрос разрешения:** прочитайте конкретное действие и путь. Чтение выбранной песни, сохранение картинок и сборка запрошенного локального видео входят в задание. Новый платёж, публикация или удаление требуют отдельного решения. Не включайте неограниченный доступ к устройству только ради закрытия сообщения.

**Картинка не подходит:** точно скажите, что изменить. Например: «Сохрани тёплые цвета, но убери выдуманную надпись; на этой картинке должна быть помощь соседу». До генерации сообщите помощнику свои предпочтения в изображении религиозных сюжетов.

## 4. Посмотрите результат

Откройте **Файлы → Загрузки → новый MP4**. Посмотрите начало, конец и несколько смен картинок; прослушайте песню целиком. Проверьте лица, руки, символы, смысл и звук. Проверка кодировщика не может определить, верно ли иллюстрация выражает вашу веру.

В результате должны быть MP4 на полную песню, извлечённый текст, файл плана сцен в формате JSON и картинки. JSON — текстовый файл для помощника; редактировать его вручную не нужно. Помощник должен сообщить длительность, размер, число картинок и сцен, а также результат проверки.

## 5. Решите, делиться ли видео

В TikTok откройте выбор файлов для загрузки, выберите **Видео** или **Загрузки** и найдите точное имя MP4. Если его нет, закройте и снова откройте окно выбора. Необязательный шаг добавления файла в каталог медиа Android описан в [руководстве по решению проблем](troubleshooting.md).

Перед публикацией просмотрите выбранный файл целиком. При загрузке проверьте актуальные ограничения вашей учётной записи на платформе и способы указать использование ИИ. Честно сообщайте об участии ИИ; не называйте сгенерированные иллюстрации документальными кадрами. Скилл готовит локальное видео и не публикует его за вас.

Правки можно просить обычным языком: «Замени только третью картинку; сохрани полный звук и сделай ещё одну версию». Не удаляйте предыдущий результат, пока не проверите замену.
