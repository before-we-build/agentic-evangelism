# Если что-то не работает

[Українська](../uk/troubleshooting.md) · Русский · [English](../en/troubleshooting.md)

Это подробный справочник для того, кто помогает с настройкой. Если вы здесь впервые, начните с [короткой помощи](help.md).

Начните с точного текста ошибки и экрана, на котором она возникла: Android, Termux, Ubuntu или Codex. Скопируйте короткое сообщение об ошибке, а не весь частный сеанс или настройки. Перед обращением за публичной помощью скройте коды входа, токены, адреса электронной почты и личные имена файлов.

## Команда не найдена

`pkg` и `termux-setup-storage` выполняются в **Termux**. `apt`, установленный `ffmpeg` и `codex` из этого руководства — в **Ubuntu**. Если вы внутри Ubuntu и нужен Termux, сначала выйдите из Codex, затем введите `exit` в командной строке Ubuntu. Снова войти в Ubuntu можно так:

```sh
proot-distro login ubuntu --bind /storage/emulated/0:/storage/emulated/0
```

Если `codex` по-прежнему не найден внутри Ubuntu, проверьте шаг установки через npm. При ошибке npm о движке или версии сохраните результат `node --version` и текст ошибки, прежде чем пробовать другой установщик. Не запускайте скачанные программы «исправления» из неизвестного источника.

## Вход в Codex не завершается

Держите терминал открытым, пока входите в браузере на том же телефоне. Временный код может истечь; снова запустите команду входа, чтобы получить новый. Если вход по коду устройства запрещён, проверьте настройки учётной записи или используйте обычный вход через браузер командой `codex login`. Никогда не вставляйте данные входа в чат. [Справка по входу](https://developers.openai.com/codex/auth/).

## Папки загрузок нет или доступ запрещён

В настройках Android проверьте разрешение Termux на доступ к файлам. Если доступ ещё не предоставлен, выполните `termux-setup-storage` в Termux. Снова войдите в Ubuntu командой подключения хранилища выше и проверьте:

```sh
ls /storage/emulated/0/Download
```

Руководство использует этот полный путь напрямую. Удобная ссылка вроде `~/storage/downloads` необязательна. Не создавайте заново и не перезаписывайте существующую папку ради совпадения пути.

## Скилла нет в списке

Перезапустите Codex и проверьте `/skills`. По умолчанию установщик использует `~/.agents/skills/suno-tiktok-video`. В старой установке может быть другая папка. Спросите Codex, из какой папки он действительно загружает скиллы. Если он явно использует `~/.codex/skills`, выйдите из Codex и выполните внутри проекта:

```sh
python3 scripts/install_skill.py --destination ~/.codex/skills
```

Не устанавливайте дубликаты в разные места просто ради перебора вариантов. Если установщик сообщает о существующей копии, он намеренно оставил её без изменений. Попросите помощника сравнить две папки и подготовить обновление для проверки или используйте явный путь `skills/suno-tiktok-video/SKILL.md` из репозитория для текущего задания. Копирование скилла не добавит недоступный инструмент изображений.

## Агент сообщает об ошибке песочницы или bwrap

На проверенном телефоне Android ARM64, в Ubuntu под Termux/PRoot с Codex CLI 0.154.0 многократно возникало `bwrap: Can't get type of source /tmp/codex-bwrap-synthetic-mount-targets-0: No such file or directory`. Запрошенная команда ещё не запускалась. Каталог был виден через `ls`, но `bwrap` не мог подключить его по виртуальному пути `/tmp`; подключение того же каталога по реальному пути rootfs PRoot проходило. На этом телефоне проблема локализована на границе преобразования путей PRoot и `bwrap`. Это не доказывает, что все установки PRoot ведут себя одинаково.

**Где: в командной строке Ubuntu внутри Termux, после выхода из Codex.** Проверьте те же настройки песочницы, не меняя конфигурацию Codex:

```sh
rootfs=$(readlink -f /proc/self/root)
TMPDIR="$rootfs/tmp" codex sandbox -c sandbox_mode=workspace-write -c sandbox_workspace_write.exclude_slash_tmp=true -- /bin/true
echo $?
```

**Ожидаемый результат:** команда песочницы ничего не выводит, а `echo $?` показывает `0`. На проверенном телефоне прошли и этот тест, и создание временного файла. Если тест не прошёл, сохраните короткий текст новой ошибки; не считайте заранее, что причина та же.

Чтобы открыть новый разговор с Codex с этими настройками, в той же Ubuntu выполните:

```sh
rootfs=$(readlink -f /proc/self/root)
TMPDIR="$rootfs/tmp" codex -c sandbox_workspace_write.exclude_slash_tmp=true
```

**Ожидаемый результат:** Codex открывается как обычно. Повторяйте эту команду для следующих сеансов или попросите помощника подготовить и проверить запускатель `~/.local/bin/codex`, который задаёт оба параметра и вызывает настоящий исполняемый файл Codex. На проверенном телефоне такой запускатель установлен и проверен через `codex sandbox`; полная установка на чистом телефоне и все интерактивные сценарии не проверялись. Перед использованием запускателя проверьте `command -v codex`. Не выбирайте неограниченный доступ как настройку по умолчанию. Если управляемая среда запрещает этот способ, остановитесь и обратитесь к её администратору.

## Сборка видео остановилась или выходной файл уже существует

Сохраните исходную песню и предыдущее видео. Используйте новое имя выходного файла; вспомогательная программа намеренно отказывается перезаписывать файлы. Попросите помощника проверить свободное место, доступ к файлам, формат звука и совпадение суммы длительностей сцен с точной длиной песни. Все указанные изображения должны существовать. Неполный MP4 не считается готовым результатом.

Во время долгой сборки держите Termux открытым. Если Android постоянно останавливает его в фоне, проверьте настройки батареи телефона для Termux. Названия меню зависят от производителя. Горячему телефону может понадобиться время на охлаждение; не перезапускайте множество сборок подряд.

## Видео есть в «Файлах», но его нет в TikTok

Сначала откройте MP4 через **Файлы → Загрузки**. Закройте и заново откройте выбор файлов TikTok, выберите «Видео» или «Обзор/Загрузки» и ищите точное имя файла. Короткое имя облегчает поиск; не установлено, что причиной зафиксированной проблемы была кириллица.

Если это не помогло, запросите сканирование без ADB. На телефоне выполните команду в Termux или Ubuntu/PRoot с подключённым путём Termux, заменив `TikTok_song.mp4` реальным именем готового видео:

```sh
/data/data/com.termux/files/usr/bin/am broadcast --user 0 \
  -a android.intent.action.MEDIA_SCANNER_SCAN_FILE \
  -d file:///storage/emulated/0/Download/TikTok_song.mp4
```

Ожидаемый ответ: `Broadcast sent without waiting for result`. Немного подождите, заново откройте выбор TikTok и ищите в «Видео» или Downloads. На телефоне проекта пользователь подтвердил видимость `TikTok_Blazhenni.mp4` после этого запроса. Сам ответ не подтверждает индексацию; если файла всё ещё нет, воспользуйтесь «Файлами» или необязательным способом ADB ниже. Для имён, требующих закодированного URI, смотрите [справку скилла для Android](../../skills/suno-tiktok-video/references/android.ru.md).

ADB — необязательный резервный способ для уже подключённого телефона. Следующий продвинутый путь также применялся на телефоне проекта; другая версия Android может вести себя иначе.

### Необязательно: подключите телефон к самому себе через ADB

В Android 11 и новее есть беспроводная отладка. Используйте доверенную сеть Wi-Fi. Откройте **Настройки → О телефоне** и несколько раз нажмите **Номер сборки**, пока не включатся параметры разработчика; у некоторых производителей этот пункт находится в сведениях о программном обеспечении. Откройте **Для разработчиков → Беспроводная отладка**, включите её и выберите **Подключить устройство с помощью кода сопряжения**. Названия могут отличаться. [Инструкции Android по ADB](https://developer.android.com/tools/adb#wireless-android11-command-line).

Оставьте окно сопряжения видимым, разделив экран с Termux. В зафиксированной попытке переключение в другое приложение закрывало это окно и приводило к `connection refused`.

**Внутри Ubuntu** при необходимости установите ADB:

```sh
apt update
apt install adb
```

Следующие команды — шаблоны, их нельзя вставлять без изменений. Возьмите `PHONE_ADDRESS` и `PAIR_PORT` из **окна с кодом сопряжения** и подставьте их ниже. Введите код сопряжения только в локальном терминале, когда он его запросит:

```sh
adb pair PHONE_ADDRESS:PAIR_PORT
```

После успешного сопряжения вернитесь на **основной экран беспроводной отладки**. Указанные там IP-адрес и порт — это `PHONE_ADDRESS` и `CONNECT_PORT` для следующей команды. Этот порт подключения отличается от порта сопряжения:

```sh
adb connect PHONE_ADDRESS:CONNECT_PORT
adb devices
```

Признак успеха: ваше устройство появляется со статусом `device`. Ниже вместо `SERIAL` используйте идентификатор из вывода `adb devices`. Никогда не копируйте старый адрес из чужих инструкций. Если устройств несколько, явно выберите нужный телефон.

### Необязательно: просканируйте и проверьте один готовый файл

Если файл действительно называется `TikTok_song.mp4`, замените `SERIAL` и выполните:

```sh
adb -s SERIAL shell ls -l /storage/emulated/0/Download/TikTok_song.mp4
adb -s SERIAL shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE -d file:///storage/emulated/0/Download/TikTok_song.mp4
adb -s SERIAL shell content query --uri content://media/external/video/media --projection _id:_display_name:relative_path --where "\"_display_name='TikTok_song.mp4'\""
```

Во всех трёх командах одинаково укажите настоящее имя выходного файла. Если оно содержит пробелы или специальные символы, попросите помощника правильно расставить кавычки. Успешная отправка сообщения `broadcast` сама по себе не подтверждает результат: последний запрос должен показать имя файла и `relative_path=Download/`. Если записи нет, немного подождите и повторите запрос один раз. Если её всё ещё нет, сообщите, что добавление в каталог не подтверждено, и используйте «Файлы»; не меняйте системные разрешения вслепую.

После успешного сканирования снова откройте выбор файлов. По окончании выключите беспроводную отладку. Добавление в каталог не означает, что видео загружено в сервис или опубликовано.
